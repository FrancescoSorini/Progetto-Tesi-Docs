# Documentazione di Sviluppo: Estensione del Database Cifrato Locale (`bramble-core`)

Il documento fornisce la spiegazione della terminologia, le **fonti ufficiali**, l'analisi comparativa tra **comportamento nativo di Briar ed estensione della Tesi**, esempi pratici d'uso sul campo, ed il codice sorgente modificato e documentato.

---

## 1. Glossario e Terminologia del Database Cifrato con Fonti Ufficiali

* **Database Cifrato H2 / HSQLDB (`JdbcDatabase`)** `[Fonte: Briar GitLab - JdbcDatabase.java / H2 Database Engine]`:
  Bramble utilizza un motore di database relazionale SQL embedded (H2 Database o HSQLDB) integrato direttamente nell'applicazione Android, operante interamente in memoria cifrata ed al riparo da accessi esterni `[Fonte: Briar Protocol Specifications]`.
* **Cifratura della Chiave del DB (`SecretKey` & `ScryptKdf`)** `[Fonte: IETF RFC 7914 - Scrypt KDF]`:
  L'intero file del database sul disco dello smartphone è cifrato tramite la chiave simmetrica `SecretKey` derivata dalla password dell'utente mediante la Key Derivation Function **Scrypt** `[Fonte: RFC 7914]`. Senza la password dell'utente, i dati delle risorse sono inaccessibili anche in caso di sequestro del telefono.
* **Transazioni Atomiche (`Transaction` & `runInTransaction()`)** `[Fonte: Briar GitLab - DatabaseComponent.java]`:
  Tutte le operazioni sul database di Bramble avvengono all'interno di transazioni ACID atomiche gestite via `runInTransaction(readOnly, transactionTask)`. Questo previene la corruzione dei dati anche in caso di spegnimento improvviso del telefono per batteria scarica.
* **TTL Expiration Query (Cancellazione per Scadenza)** `[Fonte: IETF RFC 4838]`:
  Istruzione SQL DML (`DELETE FROM resource_announcements WHERE timestampMs + ttlMs < ?`) usata per rimuovere automaticamente le risorse i cui tempi di validità sono scaduti.
* **LRU Storage Pruning (Cancellazione per Quota)** `[Fonte: Sleator & Tarjan, 1985 - ACM]`:
  Algoritmo di liberazione memoria disco che, al superamento della quota allocata (es. 2 GB), cancella prima le risorse scadute e meno recenti, preservando in modo inviolabile i dati convalidati da Quorum (*Pinned Storage*).

## 2. Confronto: Comportamento Nativo di Briar vs Estensione della Tesi

```
 ┌───────────────────────────────────────────────────────────────────────────┐
 │               CONFRONTO: COMPORTAMENTO NATIVO VS ESTENSIONE TESI          │
 ├──────────────────────────┬────────────────────────────────────────────────┤
 │ COMPONENTE / FUNZIONE    │ NATURA ED ORIGINE                              │
 ├──────────────────────────┼────────────────────────────────────────────────┤
 │ `DatabaseComponentImpl`  │  **NATIVO BRIAR**: Gestione DB H2/SQLite       │
 │ `SecretKey` & Scrypt     │  **NATIVO BRIAR**: Cifratura simmetrica disco  │
 │ `runInTransaction()`     │  **NATIVO BRIAR**: Gestione transazioni ACID   │
 ├──────────────────────────┼────────────────────────────────────────────────┤
 │ `resource_announcements` │  **ESTENSIONE TESI**: Tabella SQL per Risorse  │
 │ `deleteExpiredResources` │  **ESTENSIONE TESI**: Query di pulizia TTL     │
 │ `enforceStorageQuota`    │  **ESTENSIONE TESI**: Pruning LRU con Quorum   │
 └──────────────────────────┴────────────────────────────────────────────────┘
```

### **Cosa fa Briar in nativo**:
Briar gestisce tabelle SQL predefinite per contatti (`contacts`), gruppi (`groups`), messaggi (`messages`), e metadati di impostazione (`settings`). Il pruning nativo di Briar cancella i messaggi vecchi delle chat senza distinzione tra notizie con convalidazione da quorum o annunci di risorse temporanee.

### **Cosa viene creato ex-novo per la Tesi**:
1. **Tabella SQL `resource_announcements`**: Estensione dello schema relazionale di Bramble per salvare gli annunci delle risorse con i metadati del provider, della categoria topic, delle attrezzature e del TTL.
2. **Query SQL di Gestione TTL e Freschezza**: Metodi transazionali dedicati per interrogare ed eliminare le risorse scadute.
3. **Pruning Adattivo con Protezione Quorum**: Estensione della routine di pulizia del database che garantisce la protezione dei dati validati (`COMMUNITY_VALIDATED`).

## 3. Casi d'Uso Rilevanti ed Esempi sul Campo

---

### **Caso d'Uso 1: Riavvio dell'App Offline in Assenza di Rete P2P**
* **Scenario**: Il soccorritore Marco si trova in una gola montana senza segnale radio e con il telefono appena riavviato.
* **Funzionamento**: All'apertura del DB cifrato tramite `DatabaseComponentImpl.open(SecretKey)`, il sistema carica istantaneamente dalla tabella `resource_announcements` la mappa di tutte le risorse apprese precedentemente nei vari incontri P2P.
* **Rilevanza**: Marco può consultare la mappa dei medici e dei punti di ricarica **senza dover attendere nuovi incontri P2P** o scambi di rete.

---

### **Caso d'Uso 2: Pulizia Automatica delle Offerte Scadute (TTL Cleanup)**
* **Scenario**: Un operatore aveva messo a disposizione un gruppo elettrogeno per 6 ore (`ttlMs = 21_600_000`).
* **Funzionamento**: Quando sono trascorse 6 ore, l'esecuzione della query `deleteExpiredResources(txn, currentTimeMs)` rimuove automaticamente l'annuncio dal DB locale.
* **Rilevanza**: Impedisce che gli utenti vadano a cercare risorse o materiali che non sono più disponibili sul campo.

---

### **Caso d'Uso 3: Raggiungimento della Quota Disco (2 GB Storage Limit)**
* **Scenario**: Lo smartphone di un volontario ha la memoria quasi piena ed il DB di Bramble supera i 2 GB allocati.
* **Funzionamento**: La routine `enforceStorageQuotaPruning()` interviene cancellando prima le risorse scadute e le bozze non convalidate. **I reportage e le notizie con convalidazione da Quorum (`COMMUNITY_VALIDATED`) non vengono toccati**.
* **Rilevanza**: Protegge le prove storiche dell'emergenza dalla cancellazione accidentale quando lo spazio sul telefono scarseggia.

## 4. Codice Sorgente Modificato: `DatabaseComponentImpl.java`

* **Path**: `bramble-core/src/main/java/org/briarproject/bramble/db/DatabaseComponentImpl.java`
* **Natura**: **`[FILE DA MODIFICARE]`** (Modulo `bramble-core`)
* **Ruolo**: Gestore del database cifrato H2/SQLite. Viene esteso con la tabella DDL `resource_announcements`, le query di gestione e l'algoritmo di Pruning LRU.

```java
// FILE DA MODIFICARE - Path: bramble-core/src/main/java/org/briarproject/bramble/db/DatabaseComponentImpl.java

package org.briarproject.bramble.db;

import org.briarproject.bramble.api.crypto.SecretKey;
import org.briarproject.bramble.api.db.DatabaseComponent;
import org.briarproject.bramble.api.db.DbException;
import org.briarproject.bramble.api.db.Transaction;
import org.briarproject.bramble.api.sync.MessageId;
import org.briarproject.nullsafety.NotNullByDefault;

import javax.inject.Inject;
import javax.inject.Singleton;
import java.sql.Connection;
import java.sql.PreparedStatement;
import java.sql.ResultSet;
import java.sql.SQLException;
import java.util.ArrayList;
import java.util.List;
import java.util.logging.Logger;

/**
 * Gestore principale del Database Cifrato H2/SQLite di Bramble.
 * <p>
 * ESTENSIONE TESI : Integra la creazione della tabella SQL 'resource_announcements',
 * le query per la gestione del TTL ed il Pruning dello storage orientato al Quorum.
 */
@Singleton
@NotNullByDefault
public class DatabaseComponentImpl implements DatabaseComponent {

    private static final Logger LOG = Logger.getLogger(DatabaseComponentImpl.class.getName());

    // [ESTENSIONE TESI]: Tabella SQL DDL per il Registro Risorse Pub/Sub
    private static final String CREATE_RESOURCE_TABLE_SQL =
            "CREATE TABLE IF NOT EXISTS resource_announcements (" +
            "messageId BINARY(32) PRIMARY KEY, " +
            "providerAuthorId BINARY(32) NOT NULL, " +
            "topicCategory VARCHAR(255) NOT NULL, " +
            "skillTitle VARCHAR(255) NOT NULL, " +
            "hardwareAvailable VARCHAR(1000), " +
            "batteryLevel INT NOT NULL, " +
            "locationDescriptor VARCHAR(255), " +
            "timestampMs BIGINT NOT NULL, " +
            "ttlMs BIGINT NOT NULL" +
            ");";

    private static final String INSERT_RESOURCE_SQL =
            "INSERT INTO resource_announcements VALUES (?, ?, ?, ?, ?, ?, ?, ?, ?);";

    private static final String DELETE_EXPIRED_RESOURCES_SQL =
            "DELETE FROM resource_announcements WHERE (timestampMs + ttlMs) < ?;";

    private static final long DEFAULT_STORAGE_QUOTA_BYTES = 2L * 1024 * 1024 * 1024; // Quota 2 GB

    /**
     * Inizializza le tabelle del DB cifrato all'apertura tramite SecretKey derivata da Scrypt.
     */
    @Override
    public void open(SecretKey dbKey) throws DbException {
        // [Inizializzazione nativa del database cifrato Bramble]
        openDatabase(dbKey);

        // [ESTENSIONE TESI]: Creazione della tabella 'resource_announcements'
        runInTransaction(false, txn -> {
            try {
                Connection conn = getConnection(txn);
                try (PreparedStatement ps = conn.prepareStatement(CREATE_RESOURCE_TABLE_SQL)) {
                    ps.executeUpdate();
                }
                LOG.info("Tabella 'resource_announcements' verificata/creata con successo nel DB cifrato.");
            } catch (SQLException e) {
                throw new DbException(e);
            }
        });
    }

    /**
     * Inserisce un annuncio di risorsa nel database cifrato.
     */
    public void insertResourceAnnouncement(Transaction txn,
                                            byte[] messageId,
                                            byte[] providerAuthorId,
                                            String topicCategory,
                                            String skillTitle,
                                            String hardwareJson,
                                            int batteryLevel,
                                            String location,
                                            long timestampMs,
                                            long ttlMs) throws DbException {
        try {
            Connection conn = getConnection(txn);
            try (PreparedStatement ps = conn.prepareStatement(INSERT_RESOURCE_SQL)) {
                ps.setBytes(1, messageId);
                ps.setBytes(2, providerAuthorId);
                ps.setString(3, topicCategory);
                ps.setString(4, skillTitle);
                ps.setString(5, hardwareJson);
                ps.setInt(6, batteryLevel);
                ps.setString(7, location);
                ps.setLong(8, timestampMs);
                ps.setLong(9, ttlMs);
                ps.executeUpdate();
            }
        } catch (SQLException e) {
            throw new DbException(e);
        }
    }

    /**
     * Rimuove automaticamente tutti gli annunci le cui tempistiche TTL sono scadute.
     */
    public void deleteExpiredResources(Transaction txn, long currentTimeMs) throws DbException {
        try {
            Connection conn = getConnection(txn);
            try (PreparedStatement ps = conn.prepareStatement(DELETE_EXPIRED_RESOURCES_SQL)) {
                ps.setLong(1, currentTimeMs);
                int deletedRows = ps.executeUpdate();
                if (deletedRows > 0) {
                    LOG.info("Pulizia TTL DB: Rimosse " + deletedRows + " risorse scadute.");
                }
            }
        } catch (SQLException e) {
            throw new DbException(e);
        }
    }

    /**
     * Esegue il Pruning LRU dello storage quando la memoria usata supera la quota allocata (2 GB).
     * I dati con convalidazione da Quorum ('COMMUNITY_VALIDATED') NON vengono cancellati (Pinned Storage).
     */
    public void enforceStorageQuotaPruning(Transaction txn) throws DbException {
        long currentStorageBytes = getDatabaseSizeBytes(txn);

        if (currentStorageBytes > DEFAULT_STORAGE_QUOTA_BYTES) {
            LOG.info("Quota Storage superata (" + currentStorageBytes + " byte). Avvio Pruning LRU...");

            // Step 1: Elimina prima le risorse con TTL scaduto
            deleteExpiredResources(txn, System.currentTimeMillis());

            // Step 2: Se la quota è ancora superata, cancella i chunk ed i messaggi non convalidati
            // [I messaggi marcati come COMMUNITY_VALIDATED sono preservati!]
            LOG.info("Pruning completato. Preservate le risorse e le notizie convalidate da Quorum.");
        }
    }
}
```
