# Documentazione di Sviluppo: Client Pub/Sub e Pubblicazione Annunci (`briar-core`)

Questo documento è focalizzato sull'implementazione del **Client Pub/Sub per la creazione, codifica BDF, firma Ed25519 e sottomissione al motore Bramble Sync Protocol degli annunci di risorsa (`ResourceDiscoveryClientImpl.java`)**.

Il documento fornisce la spiegazione della terminologia protocollare, le **fonti ufficiali**, l'analisi comparativa tra **comportamento nativo di Briar ed estensione della Tesi**, esempi pratici d'uso sul campo, ed il codice sorgente completo e documentato.

---

## 1. Glossario e Terminologia Protocollare con Fonti Ufficiali

* **`ClientId`** `[Fonte: Briar GitLab - ClientId.java / Bramble Specifications]`:
  Identificatore stringa univoco a livello di protocollo (es. `org.briarproject.briar.resource.pubsub`) che notifica a Bramble quale client applicativo debba gestire ed interpretare i messaggi BDF associati ad un gruppo.
* **`GroupFactory` & `Group`** `[Fonte: Briar GitLab - GroupFactory.java / Group.java]`:
  Servizio di fabbrica che genera l'oggetto `Group` di sincronizzazione. Ciascun `Group` possiede un `GroupId` a 32 byte ottenuto calcolando l'hash SHA-256 unendo il `ClientId` ed il descrittore del gruppo (il nome del Topic Pub/Sub, es. `#medici-pronto-soccorso`).
* **`GroupVisibility` (Visibilità del Gruppo BSS)** `[Fonte: Briar GitLab - DatabaseComponent.java]`:
  Proprietà del database di Bramble che abilita la sincronizzazione epidemica per un dato `GroupId`. Quando `db.setGroupVisibility(txn, groupId, true)` è abilitato, il motore Bramble Sync include automaticamente i messaggi del gruppo nei record BSS `OFFER` inviati ai peer vicini.
* **`ClientHelper` (Codifica BDF e Firma Ed25519)** `[Fonte: Briar GitLab - ClientHelper.java / RFC 8032]`:
  Componente di utilità che converte gli oggetti Java in strutture `BdfList`, esegue la firma crittografica asimmetrica Ed25519 con la chiave privata dell'utente (`clientHelper.sign`), impacchetta l'header ed inserisce il messaggio nel DB cifrato.
* **Metadato `shared = true`** `[Fonte: Briar Protocol Specifications - BSS Protocol]`:
  Flag booleano passato a `clientHelper.addLocalMessage(txn, message, meta, true)`. Comunica al motore di sincronizzazione P2P che il messaggio non è solo locale, ma deve essere diffuso epidemiologicamente agli altri nodi vicini (*Store-Carry-and-Forward*).

## 2. Confronto: Comportamento Nativo di Briar vs Estensione della Tesi

```
 ┌────────────────────────────────────────────────────────────────────────────┐
 │               CONFRONTO: COMPORTAMENTO NATIVO VS ESTENSIONE TESI           │
 ├───────────────────────────┬────────────────────────────────────────────────┤
 │ COMPONENTE / FUNZIONE     │ NATURA ED ORIGINE                              │
 ├───────────────────────────┼────────────────────────────────────────────────┤
 │ `ClientId`, `GroupFactory`│  **NATIVO BRIAR**: Gestione gruppi e moduli    │
 │ `setGroupVisibility()`    │  **NATIVO BRIAR**: Abilitazione sync BSS       │
 │ `clientHelper.sign()`     │  **NATIVO BRIAR**: Firma asimmetrica Ed25519   │
 ├───────────────────────────┼────────────────────────────────────────────────┤
 │ `ResourceDiscoveryClient` │  **ESTENSIONE TESI**: Client Pub/Sub Risorse   │
 │ `CLIENT_ID_RESOURCE`      │  **ESTENSIONE TESI**: ClientId del modulo      │
 │ `publishResource...()`    │  **ESTENSIONE TESI**: Routine Pub/Sub Risorsa  │
 └───────────────────────────┴────────────────────────────────────────────────┘
```

### **Cosa fa Briar in nativo**:
Briar usa `ClientHelper` e `GroupFactory` per creare i gruppi e pubblicare messaggi nei forum di discussione o nelle chat tra contatti aggiunti in rubrica. La sincronizzazione dei gruppi richiede che gli utenti si aggiungano prima reciprocamente come contatti 1-a-1.

### **Cosa viene creato ex-novo per la Tesi**:
1. **`ResourceDiscoveryClientImpl.java`**: Un nuovo client di servizio dedicato che automatizza la creazione dinamica del `Group` per ciascun Topic di competenza, abilita la `GroupVisibility` nel DB e firma il messaggio BDF `ResourceAnnouncementMessage`.
2. **Disaccoppiamento dai Contatti Diretti (Pub/Sub Broadcast)**: Non richiede l'aggiunta reciproca dei contatti in rubrica. Chiunque sottoscrive il Topic della risorsa riceve automaticamente gli annunci pubblicati dai nodi entro il raggio P2P o appresi per inoltro epidemico.

## 3. Casi d'Uso Rilevanti ed Esempi sul Campo

---

### **Caso d'Uso 1: Pubblicazione con 1-Click di un Medico sul Campo**
* **Scenario**: Il dottor Marco arriva in una piazza di raccolta d'emergenza. Apre l'app e seleziona la scheda *"Pubblica Competenza"*.
* **Esecuzione**:
  L'interfaccia UI invoca `ResourceDiscoveryClientImpl.publishResourceAnnouncement()`:
  1. Il client genera istantaneamente il `Group` per `#medici-pronto-soccorso`.
  2. Codifica in BDF i dati di Marco: *"Medico Traumatologo con Kit"*, livello batteria 90%, settore "Piazza Nord".
  3. Firma il messaggio BDF con la chiave privata Ed25519 di Marco.
  4. Imposta `shared = true` nel DB di Bramble.
* **Rilevanza**: Non appena il telefono di Marco rileva altri smartphone via Bluetooth o Wi-Fi Direct, Bramble Sync invia il record BSS `OFFER` diffondendo l'annuncio medico.

---

### **Caso d'Uso 2: Messa a Disposizione di una Stazione Ricarica / Gruppo Elettrogeno**
* **Scenario**: Il volontario Giuseppe attiva un gruppo elettrogeno a benzina e vuole notificare ai soccorritori la presenza di prese USB libere.
* **Esecuzione**:
  Giuseppe seleziona il Topic `#punti-ricarica-energia`. `ResourceDiscoveryClientImpl` crea il messaggio BDF con hardware = `["Gruppo Elettrogeno 3kW", "Multipresa USB"]` e TTL = 6 ore.
* **Rilevanza**: L'annuncio viene firmato, salvato con `shared = true` e reso disponibile per lo scambio epidemico con tutti i soccorritori di passaggio.

---

### **Caso d'Uso 3: Sottoscrizione Automatica ad un Topic di Risorse da parte di un'ONG**
* **Scenario**: La squadra della Protezione Civile vuole ricevere tutti gli annunci relativi a pompieri e squadre di ricerca macerie.
* **Esecuzione**:
  L'ONG invoca `subscribeToResourceTopic("#squadre-ricerca-macerie")`. Il client invoca `db.setGroupVisibility(txn, topicGroupId, true)`.
* **Rilevanza**: All'incontro P2P con qualsiasi nodo della rete, Bramble Sync scopre che l'ONG è interessata a quel Topic e le trasferisce tutti gli annunci rilevanti memorizzati nello sciame.

## 4. Codice Sorgente Completo: `ResourceDiscoveryClientImpl.java`

* **Path**: `briar-core/src/main/java/org/briarproject/briar/resource/ResourceDiscoveryClientImpl.java`
* **Natura**: **`[FILE NUOVO]`** (Modulo `briar-core`)
* **Ruolo**: Implementazione della business logic per la pubblicazione e sottoscrizione Pub/Sub dei messaggi di risorsa.

```java
// FILE NUOVO - Path: briar-core/src/main/java/org/briarproject/briar/resource/ResourceDiscoveryClientImpl.java

package org.briarproject.briar.resource;

import org.briarproject.bramble.api.ClientHelper;
import org.briarproject.bramble.api.data.BdfDictionary;
import org.briarproject.bramble.api.data.BdfList;
import org.briarproject.bramble.api.db.DatabaseComponent;
import org.briarproject.bramble.api.db.DbException;
import org.briarproject.bramble.api.identity.Author;
import org.briarproject.bramble.api.identity.IdentityManager;
import org.briarproject.bramble.api.sync.ClientId;
import org.briarproject.bramble.api.sync.Group;
import org.briarproject.bramble.api.sync.GroupFactory;
import org.briarproject.bramble.api.sync.Message;
import org.briarproject.briar.api.resource.ResourceDiscoveryClient;

import javax.inject.Inject;
import javax.inject.Singleton;
import java.util.List;
import java.util.logging.Logger;

/**
 * Implementazione del Client Pub/Sub per la scoperta e pubblicazione delle risorse di rete.
 * ESTENSIONE TESI: Gestisce la creazione dinamica dei gruppi Bramble per Topic,
 * la codifica BDF, la firma Ed25519 e la sottomissione al motore di sincronizzazione P2P BSS.
 *
 * @author Progetto Tesi Giornalismo P2P
 */
@Singleton
public class ResourceDiscoveryClientImpl implements ResourceDiscoveryClient {

    private static final Logger LOG = Logger.getLogger(ResourceDiscoveryClientImpl.class.getName());

    // ClientId univoco a livello di protocollo per il modulo Pub/Sub delle risorse
    public static final ClientId CLIENT_ID_RESOURCE_PUBSUB = new ClientId("org.briarproject.briar.resource.pubsub");

    // Codice tipo messaggio BDF per l'annuncio della risorsa
    public static final int MSG_TYPE_RESOURCE_ANNOUNCEMENT = 10;

    private final DatabaseComponent db;
    private final ClientHelper clientHelper;
    private final IdentityManager identityManager;
    private final GroupFactory groupFactory;

    @Inject
    public ResourceDiscoveryClientImpl(DatabaseComponent db,
                                       ClientHelper clientHelper,
                                       IdentityManager identityManager,
                                       GroupFactory groupFactory) {
        this.db = db;
        this.clientHelper = clientHelper;
        this.identityManager = identityManager;
        this.groupFactory = groupFactory;
    }

    /**
     * 1. Pubblica le proprie competenze/risorse su uno specifico Topic Pub/Sub della comunità.
     */
    @Override
    public void publishResourceAnnouncement(String topicCategory,
                                            String skillTitle,
                                            List<String> hardwareAvailable,
                                            int batteryLevelPercent,
                                            String locationDescriptor,
                                            long ttlMs) throws Exception {

        long timestampMs = System.currentTimeMillis();
        Author localAuthor = identityManager.getLocalAuthor();

        // Step A: Generazione o recupero del Gruppo Bramble per il Topic della risorsa
        Group topicGroup = groupFactory.createGroup(CLIENT_ID_RESOURCE_PUBSUB, topicCategory.getBytes());

        // Step B: Costruzione della struttura BDF (BdfList) del corpo da firmare
        BdfList bodyToSign = BdfList.of(
            MSG_TYPE_RESOURCE_ANNOUNCEMENT,
            clientHelper.toList(localAuthor),
            topicCategory,
            skillTitle,
            BdfList.of(hardwareAvailable),
            batteryLevelPercent,
            locationDescriptor,
            timestampMs,
            ttlMs
        );

        // Step C: Firma digitale asimmetrica Ed25519 con la chiave privata dell'utente
        byte[] signature = clientHelper.sign(
            "org.briarproject.briar.resource/RESOURCE_ANNOUNCEMENT",
            bodyToSign,
            localAuthor.getPrivateKey()
        );

        // Step D: Assemblaggio del payload BDF finale
        BdfList fullBody = BdfList.of(bodyToSign, signature);
        byte[] bodyBytes = clientHelper.toByteArray(fullBody);

        // Step E: Creazione del messaggio Bramble Sync per il Gruppo
        Message message = clientHelper.createMessage(topicGroup.getId(), timestampMs, bodyBytes);

        // Step F: Salvataggio transazionale nel DB cifrato con shared = true per l'inoltro epidemico P2P
        db.runInTransaction(false, txn -> {
            if (!db.containsGroup(txn, topicGroup.getId())) {
                db.addGroup(txn, topicGroup);
            }

            // Abilita la visibilità del gruppo per Bramble Sync
            db.setGroupVisibility(txn, topicGroup.getId(), true);

            BdfDictionary metadata = new BdfDictionary();
            metadata.put("type", MSG_TYPE_RESOURCE_ANNOUNCEMENT);
            metadata.put("topicCategory", topicCategory);
            metadata.put("read", true);

            // shared = true comunica a Bramble BSS di offrire questo messaggio ai peer vicini
            clientHelper.addLocalMessage(txn, message, metadata, true);
        });

        LOG.info("Annuncio Risorsa pubblicato con successo sul Topic " + topicCategory + ": " + skillTitle);
    }

    /**
     * 2. Sottoscrive l'utente locale ad un Topic di risorse, abilitandone la GroupVisibility nel DB.
     */
    @Override
    public void subscribeToResourceTopic(String topicCategory) throws DbException {
        Group topicGroup = groupFactory.createGroup(CLIENT_ID_RESOURCE_PUBSUB, topicCategory.getBytes());

        db.runInTransaction(false, txn -> {
            if (!db.containsGroup(txn, topicGroup.getId())) {
                db.addGroup(txn, topicGroup);
            }
            // Abilita la sincronizzazione automatica dei messaggi appartenenti a questo Topic
            db.setGroupVisibility(txn, topicGroup.getId(), true);
        });

        LOG.info("Sottoscrizione P2P completata per il Topic Risorse: " + topicCategory);
    }
}
```
