# Documentazione di Sviluppo: Intercettazione BSS e Registro Risorse (`briar-core`)

Questo documento è focalizzato sull'implementazione del meccanismo di **intercettazione dei messaggi BDF ricevuti via Bramble Sync Protocol (`ResourceMessageHook.java`)** e sulla gestione del **Registro Locale delle Risorse con Invalida dello Stato e Scadenza TTL (`ResourceRegistryImpl.java`)**.

Il documento fornisce la spiegazione della terminologia protocollare, le **fonti ufficiali**, l'analisi comparativa tra **comportamento nativo di Briar ed estensione della Tesi**, esempi pratici d'uso sul campo, ed il codice sorgente completo e documentato.

---

## 1. Glossario e Terminologia Protocollare con Fonti Ufficiali

* **`BdfIncomingMessageHook` / `IncomingMessageHook`** `[Fonte: Briar GitLab - BdfIncomingMessageHook.java]`:
  Punto di estensione nativo di Bramble che intercetta qualsiasi messaggio in arrivo appartenente ad un determinato `ClientId` prima che venga registrato definitivamente nel DB o mostrato all'utente.
* **`DeliveryAction` (`ACCEPT`, `REJECT`, `DEFER`)** `[Fonte: Briar GitLab - IncomingMessageHook.java]`:
  Enumerazione restituita dall'hook per comunicare al motore Bramble Sync l'azione da intraprendere sul messaggio ricevuto:
  * `ACCEPT`: Il messaggio è valido, viene salvato nel DB e consegnato all'applicazione.
  * `REJECT`: Il messaggio è malevolo, corrotto o con firma fallita; viene scartato immediatamente senza essere salvato.
  * `DEFER`: La lavorazione del messaggio viene posticipata.
* **Invalida dello Stato (*State Invalidation / Overwrite*)** `[Fonte: Demers et al., 1987 - ACM PODC]`:
  Algoritmo di aggiornamento dello stato P2P in cui una nuova versione di un annuncio emessa dallo stesso provider per la medesima categoria invalida e sovrascrive la versione precedente, evitando accumuli di stati obsoleti nel DB.
* **`EventBus` ed Eventi Applicativi** `[Fonte: Briar GitLab - EventBus.java]`:
  Bus degli eventi interno di Bramble basato sul pattern *Publish-Subscribe locale*. Quando un nuovo annuncio valido viene registrato, l'hook pubblica un evento (es. `ResourceAnnouncementReceivedEvent`) per aggiornare in tempo reale la UI Android.

## 2. Confronto: Comportamento Nativo di Briar vs Estensione della Tesi

```
 ┌───────────────────────────────────────────────────────────────────────────┐
 │               CONFRONTO: COMPORTAMENTO NATIVO VS ESTENSIONE TESI          │
 ├──────────────────────────┬────────────────────────────────────────────────┤
 │ COMPONENTE / FUNZIONE    │ NATURA ED ORIGINE                              │
 ├──────────────────────────┼────────────────────────────────────────────────┤
 │ `BdfIncomingMessageHook` │  **NATIVO BRIAR**: Hook per l'intercettazione  │
 │ `DeliveryAction`         │  **NATIVO BRIAR**: Esito di validazione BSS    │
 │ `verifySignature()`      │  **NATIVO BRIAR**: Verifica firma Ed25519      │
 ├──────────────────────────┼────────────────────────────────────────────────┤
 │ `ResourceMessageHook`    │  **ESTENSIONE TESI**: Hook specifico Risorse   │
 │ `ResourceRegistryImpl`   │  **ESTENSIONE TESI**: Registro e Mappa In-Mem  │
 │ Invalida per Provider    │  **ESTENSIONE TESI**: Overwrite dello Stato    │
 └──────────────────────────┴────────────────────────────────────────────────┘
```

### **Cosa fa Briar in nativo**:
Briar usa `BdfIncomingMessageHook` per intercettare i messaggi di chat, i post dei forum o le richieste d'amicizia. Quando un messaggio arriva, Briar ne valida la firma e lo aggiunge alla lista cronologica della conversazione senza mai sovrascrivere o invalidare i messaggi precedenti dello stesso utente.

### **Cosa viene creato ex-novo per la Tesi**:
1. **`ResourceMessageHook.java`**: Un hook BDF personalizzato che intercetta i messaggi di tipo `MSG_TYPE_RESOURCE_ANNOUNCEMENT = 10`. Valida la firma Ed25519 dell'autore e verifica che il TTL dell'annuncio non sia scaduto.
2. **`ResourceRegistryImpl.java`**: Un registro locale concorrente (`ConcurrentHashMap`) integrato col DB cifrato che applica l'**Invalida dello Stato**: se un medico o un operatore aggiorna le proprie risorse, il nuovo messaggio sovrascrive quello precedente della stessa categoria, mantenendo la mappa delle risorse sempre pulita.

## 3. Casi d'Uso Rilevanti ed Esempi sul Campo

---

### **Caso d'Uso 1: Aggiornamento dello Stato di un Medico ("Materiali Esauriti")**
* **Scenario**: Il Dottor Marco ha pubblicato 2 ore prima un annuncio come *"Medico con Kit Chirurgico"*. Durante un intervento esaurisce il materiale e pubblica un nuovo annuncio: *"Medico - Materiali Esauriti"*.
* **Esecuzione**:
  1. Il nuovo messaggio viaggia via P2P BSS ed arriva sul telefono del coordinatore dell'ONG.
  2. `ResourceMessageHook` intercetta il messaggio BDF e ne valida la firma Ed25519.
  3. `ResourceRegistryImpl` riconosce la chiave del provider (`providerAuthorId + "_" + topicCategory`) e **sovrascrive lo stato precedente di Marco**.
* **Rilevanza**: La mappa delle risorse sul telefono del coordinatore si aggiorna istantaneamente, evitando di inviare feriti da un medico che ha esaurito i materiali.

---

### **Caso d'Uso 2: Pulizia Automatica delle Risorse Scadute (TTL Enforcement)**
* **Scenario**: Un operatore della Protezione Civile apre l'app per cercare idrovore disponibili nel topic `#attrezzature-idrauliche`.
* **Esecuzione dello**:
  L'app interroga `resourceRegistry.getActiveResourcesForTopic("#attrezzature-idrauliche")`:
  1. `ResourceRegistryImpl` confronta il timestamp corrente con il TTL dei singoli annunci ($t > \text{timestamp} + \text{ttl}$).
  2. Rimuove automaticamente dalla lista gli annunci pubblicati oltre 12 ore prima e non più rinnovati.
* **Rilevanza**: L'operatore visualizza solo le attrezzature verosimilmente ancora operative e presenti sul territorio.

---

### **Caso d'Uso 3: Scarto Automatico di Annunci Falsificati o Corrotti**
* **Scenario**: Un nodo malevole invia un falso annuncio di risorsa modificando il nome del provider o alterando il livello di batteria.
* **Esecuzione dello**:
  `ResourceMessageHook` esegue `clientHelper.verifySignature()`. Poiché la firma non corrisponde alla chiave pubblica dell'autore, l'hook restituisce **`DeliveryAction.REJECT`**.
* **Rilevanza**: Il messaggio malevolo viene scartato ed eliminato sul nascere senza inquinare il registro risorse o il DB locale.

### A. `ResourceMessageHook.java`
* **Path**: `briar-core/src/main/java/org/briarproject/briar/resource/ResourceMessageHook.java`
* **Natura**: **`[FILE NUOVO]`** (Modulo `briar-core`)
* **Ruolo**: Hook BDF che intercetta i messaggi di risorsa ricevuti via Bramble Sync Protocol, ne valida la firma crittografica e li passa al registro.

```java
// FILE NUOVO - Path: briar-core/src/main/java/org/briarproject/briar/resource/ResourceMessageHook.java

package org.briarproject.briar.resource;

import org.briarproject.bramble.api.ClientHelper;
import org.briarproject.bramble.api.FormatException;
import org.briarproject.bramble.api.data.BdfDictionary;
import org.briarproject.bramble.api.data.BdfList;
import org.briarproject.bramble.api.db.DatabaseComponent;
import org.briarproject.bramble.api.db.DbException;
import org.briarproject.bramble.api.event.EventBus;
import org.briarproject.bramble.api.identity.Author;
import org.briarproject.bramble.api.sync.Message;
import org.briarproject.bramble.api.sync.validation.BdfIncomingMessageHook;
import org.briarproject.briar.api.resource.ResourceAnnouncementMessage;
import org.briarproject.nullsafety.NotNullByDefault;

import javax.annotation.concurrent.Immutable;
import javax.inject.Inject;
import java.security.GeneralSecurityException;
import java.util.List;
import java.util.logging.Logger;

import static org.briarproject.briar.resource.ResourceDiscoveryClientImpl.MSG_TYPE_RESOURCE_ANNOUNCEMENT;

/**
 * Hook BDF di intercettazione dei messaggi di risorsa in arrivo dalla rete P2P Bramble.
 * ESTENSIONE TESI: Intercetta i messaggi Pub/Sub delle risorse, ne valida la firma Ed25519
 * ed aggiona il registro locale 'ResourceRegistry'.
 *
 * @author Progetto Tesi Giornalismo P2P
 */
@Immutable
@NotNullByDefault
public class ResourceMessageHook extends BdfIncomingMessageHook {

    private static final Logger LOG = Logger.getLogger(ResourceMessageHook.class.getName());

    private final DatabaseComponent db;
    private final ClientHelper clientHelper;
    private final ResourceRegistry resourceRegistry;
    private final EventBus eventBus;

    @Inject
    public ResourceMessageHook(DatabaseComponent db,
                               ClientHelper clientHelper,
                               ResourceRegistry resourceRegistry,
                               EventBus eventBus) {
        super(db, clientHelper);
        this.db = db;
        this.clientHelper = clientHelper;
        this.resourceRegistry = resourceRegistry;
        this.eventBus = eventBus;
    }

    /**
     * Intercetta ed elabora il messaggio BDF ricevuto dal motore Bramble Sync.
     */
    @Override
    protected DeliveryAction incomingMessage(Transaction txn, Message m, BdfList body, BdfDictionary meta)
            throws DbException, FormatException {

        int msgType = body.getList(0).getInt(0);

        // Gestisce solo i messaggi di tipo MSG_TYPE_RESOURCE_ANNOUNCEMENT (10)
        if (msgType == MSG_TYPE_RESOURCE_ANNOUNCEMENT) {
            return processIncomingResourceAnnouncement(m, body);
        }

        return DeliveryAction.ACCEPT;
    }

    private DeliveryAction processIncomingResourceAnnouncement(Message m, BdfList body) throws FormatException {
        try {
            // Step 1: Estrazione del corpo da firmare e della firma Ed25519
            BdfList bodyToSign = body.getList(0);
            byte[] signature = body.getRaw(1);

            Author providerAuthor = clientHelper.parseAndValidateAuthor(bodyToSign.getList(1));

            // Step 2: Verifica della firma digitale asimmetrica Ed25519
            clientHelper.verifySignature(
                signature,
                "org.briarproject.briar.resource/RESOURCE_ANNOUNCEMENT",
                bodyToSign,
                providerAuthor.getPublicKey()
            );

            // Step 3: Estrazione dei campi BDF del DTO
            String topicCategory = bodyToSign.getString(2);
            String skillTitle = bodyToSign.getString(3);
            List<String> hardware = bodyToSign.getList(4).getStringList();
            int batteryPercent = bodyToSign.getInt(5);
            String location = bodyToSign.getString(6);
            long timestampMs = bodyToSign.getLong(7);
            long ttlMs = bodyToSign.getLong(8);

            ResourceAnnouncementMessage announcement = new ResourceAnnouncementMessage(
                m.getId(),
                providerAuthor,
                topicCategory,
                skillTitle,
                hardware,
                batteryPercent,
                location,
                timestampMs,
                ttlMs,
                signature
            );

            // Step 4: Controllo di validità temporale TTL
            if (announcement.isExpired(System.currentTimeMillis())) {
                LOG.info("Messaggio risorsa ricevuto ma già scaduto -> REJECT.");
                return DeliveryAction.REJECT;
            }

            // Step 5: Registrazione nel registro locale ed invalida dello stato precedente
            resourceRegistry.registerIncomingResourceAnnouncement(announcement);

            LOG.info("Annuncio Risorsa validato e registrato con successo per: " + providerAuthor.getName());
            return DeliveryAction.ACCEPT;

        } catch (GeneralSecurityException e) {
            LOG.warning("Firma Ed25519 non valida sull'annuncio della risorsa -> REJECT.");
            return DeliveryAction.REJECT; // Scarta il messaggio malevolo
        }
    }
}
```

### B. `ResourceRegistryImpl.java`
* **Path**: `briar-core/src/main/java/org/briarproject/briar/resource/ResourceRegistryImpl.java`
* **Natura**: **`[FILE NUOVO]`** (Modulo `briar-core`)
* **Ruolo**: Gestore del registro locale delle risorse con supporto all'Invalida dello Stato ed al filtro delle risorse attive.

```java
// FILE NUOVO - Path: briar-core/src/main/java/org/briarproject/briar/resource/ResourceRegistryImpl.java

package org.briarproject.briar.resource;

import org.briarproject.bramble.api.db.DatabaseComponent;
import org.briarproject.bramble.api.db.DbException;
import org.briarproject.briar.api.resource.ResourceAnnouncementMessage;
import org.briarproject.briar.api.resource.ResourceRegistry;

import javax.inject.Inject;
import javax.inject.Singleton;
import java.util.ArrayList;
import java.util.List;
import java.util.Map;
import java.util.concurrent.ConcurrentHashMap;
import java.util.logging.Logger;

/**
 * Implementazione del Registro Locale delle Risorse per la gestione della mappa in-memory,
 * dell'invalida dello stato e del clean-up dei dati scaduti.
 * ESTENSIONE TESI
 *
 * @author Progetto Tesi Giornalismo P2P
 */
@Singleton
public class ResourceRegistryImpl implements ResourceRegistry {

    private static final Logger LOG = Logger.getLogger(ResourceRegistryImpl.class.getName());

    // Mappa locale in-memory concorrente per un accesso ad altissima velocità
    private final Map<String, ResourceAnnouncementMessage> activeResourceMap = new ConcurrentHashMap<>();
    private final DatabaseComponent db;

    @Inject
    public ResourceRegistryImpl(DatabaseComponent db) {
        this.db = db;
    }

    /**
     * 1. Registra un annuncio di risorsa ricevuto via P2P BSS ed applica la Sovrascrizione dello Stato.
     */
    @Override
    public synchronized void registerIncomingResourceAnnouncement(ResourceAnnouncementMessage announcement) {
        long now = System.currentTimeMillis();

        if (announcement.isExpired(now)) {
            LOG.info("Annuncio risorsa scartato dal registro perché scaduto.");
            return;
        }

        // Chiave univoca del provider per categoria topic (es. "AuthorId123_#medici-pronto-soccorso")
        String providerKey = announcement.getProviderAuthor().getId().getBytes() + "_" + announcement.getTopicCategory();

        // INVALIDA DELLO STATO (State Overwrite):
        // Se esiste un annuncio precedente dello stesso provider, sovrascrivi solo se il nuovo è più recente!
        ResourceAnnouncementMessage existing = activeResourceMap.get(providerKey);
        if (existing == null || announcement.getTimestampMs() > existing.getTimestampMs()) {
            activeResourceMap.put(providerKey, announcement);
            LOG.info("Mappa Risorse aggiornata (Sovrascrittura Stato) per " + announcement.getTopicCategory() +
                     " dal provider: " + announcement.getProviderAuthor().getName());
        }
    }

    /**
     * 2. Ritorna le risorse attive e non scadute per un dato Topic (usato dalla UI dell'app).
     */
    @Override
    public List<ResourceAnnouncementMessage> getActiveResourcesForTopic(String topicCategory) {
        long now = System.currentTimeMillis();
        List<String> expiredKeys = new ArrayList<>();
        List<ResourceAnnouncementMessage> activeList = new ArrayList<>();

        for (Map.Entry<String, ResourceAnnouncementMessage> entry : activeResourceMap.entrySet()) {
            ResourceAnnouncementMessage resource = entry.getValue();
            if (resource.getTopicCategory().equals(topicCategory)) {
                if (!resource.isExpired(now)) {
                    activeList.add(resource);
                } else {
                    expiredKeys.add(entry.getKey()); // Marca per il clean-up
                }
            }
        }

        // Clean-up automatico delle risorse scadute
        expiredKeys.forEach(activeResourceMap::remove);
        return activeList;
    }

    /**
     * 3. Invalida o rimuove un annuncio dal registro locale.
     */
    @Override
    public void invalidateResource(String providerAuthorId, String topicCategory) {
        String providerKey = providerAuthorId + "_" + topicCategory;
        activeResourceMap.remove(providerKey);
        LOG.info("Risorsa invalidata e rimossa dal registro per la chiave: " + providerKey);
    }
}
```
