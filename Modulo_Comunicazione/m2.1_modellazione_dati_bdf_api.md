Il documento fornisce la spiegazione dettagliata della terminologia protocollare, le **fonti ufficiali**, l'analisi comparativa tra **comportamento nativo di Briar ed estensione della Tesi**, esempi pratici d'uso sul campo, ed il codice sorgente completo delle componenti con relative annotazioni.

## 1. Glossario e Terminologia Protocollare con Fonti Ufficiali

Definiamo la terminologia tecnica del framework Bramble/Briar ricavata dalle fonti ufficiali:

* **BDF (Bramble Data Format)** `[Fonte: Briar GitLab - BDF Specification]`:
  È il formato binario di serializzazione dei dati proprietario di Bramble, basato su strutture dati fortemente tipizzate, compatte e prive di schemi esterni complessi. BDF utilizza principalmente due strutture:
  * **`BdfList`**: Una sequenza ordinata di elementi BDF (interi, stringhe, byte array, o altre BdfList) `[Fonte: Briar GitLab - BdfList.java]`.
  * **`BdfDictionary`**: Una mappa chiave-valore di elementi BDF `[Fonte: Briar GitLab - BdfDictionary.java]`.
* **`Author` & `AuthorId`** `[Fonte: Briar GitLab - Author.java / RFC 8032]`:
  Rappresenta l'identità crittografica dell'utente. Contiene lo pseudonimo (`name`), la chiave pubblica Ed25519 (`publicKey`) a 32 byte e l'`AuthorId` (hash SHA-256 a 32 byte della chiave pubblica) `[Fonte: RFC 8032]`.
* **`MessageId`** `[Fonte: Briar GitLab - MessageId.java]`:
  Identificatore immutabile e globale a 32 byte ottenuto calcolando l'hash SHA-256 dell'intestazione e del payload BDF del messaggio `[Fonte: Briar Protocol Specifications]`.
* **`ClientId`** `[Fonte: Briar GitLab - ClientId.java]`:
  Identificatore stringa univoco a livello di protocollo (es. `org.briarproject.briar.resource.pubsub`) che specifica quale modulo applicativo debba gestire ed interpretare i messaggi in arrivo `[Fonte: Briar Protocol Specifications]`.
* **`GroupId` & `Group`** `[Fonte: Briar GitLab - Group.java / GroupId.java]`:
  Descrittore del gruppo di sincronizzazione Bramble. `GroupId` è l'hash SHA-256 calcolato sul `ClientId` e sul descrittore del gruppo (il nome del Topic Pub/Sub).
* **TTL (Time-To-Live)** `[Fonte: IETF RFC 4838 - DTN Architecture]`:
  Intervallo di validità espresso in millisecondi che determina per quanto tempo l'annuncio di una risorsa rimane valido prima di scadere ed essere rimosso dal registro locale.

## 2. Confronto: Comportamento Nativo di Briar vs Estensione della Tesi

La seguente tabella evidenzia la distinzione tra ciò che è già presente nel codice nativo di Briar e ciò che costituisce l'**estensione originale sviluppata per il progetto di tesi**:

```
 ┌────────────────────────────────────────────────────────────────────────────┐
 │               CONFRONTO: COMPORTAMENTO NATIVO VS ESTENSIONE TESI           │
 ├───────────────────────────┬────────────────────────────────────────────────┤
 │ COMPONENTE / CONCETTO     │ NATURA ED ORIGINE                              │
 ├───────────────────────────┼────────────────────────────────────────────────┤
 │ `Author`, `MessageId`     │  **NATIVO BRIAR**: Classi base di identità     │
 │ `BdfList`, `BdfDictionary`│  **NATIVO BRIAR**: Formato di serializzazione  │
 │ `GroupId`, `ClientId`     │  **NATIVO BRIAR**: Gestione dei gruppi BSS     │
 ├───────────────────────────┼────────────────────────────────────────────────┤
 │ `ResourceAnnouncement`    │  **ESTENSIONE TESI**: DTO BDF per le risorse   │
 │ `ResourceDiscoveryClient` │  **ESTENSIONE TESI**: API Pub/Sub per risorse  │
 │ `ResourceRegistry`        │  **ESTENSIONE TESI**: Registro e mappa locale  │
 │ `CLIENT_ID_RESOURCE`      │  **ESTENSIONE TESI**: ClientId del modulo      │
 │ `MSG_TYPE_RESOURCE = 10`  │  **ESTENSIONE TESI**: Tipo messaggio BDF       │
 └───────────────────────────┴────────────────────────────────────────────────┘
```

### **Cosa fa Briar in nativo**:
Briar nasce come sistema per chat private 1-a-1 e gruppi/forum di discussione testuali. I messaggi BDF nativi di Briar contengono unicamente testo, timestamp ed eventualmente allegati d'immagine leggeri.

### **Cosa viene creato ex-novo**:
1. **Modello Dati della Risorsa (`ResourceAnnouncementMessage`)**: Modellazione BDF per trasportare non solo testo, ma **capacità hardware, livello della batteria dello smartphone, competenze professionali, ubicazione e TTL di validità**.
2. **Architettura Pub/Sub di Scoperta Risorse (`ResourceDiscoveryClient`)**: Disaccoppiamento tra chi cerca una risorsa (sottoscrizione ad un topic) e chi la offre, senza bisogno che i due nodi si conoscano preventivamente come contatti reciproci in rubrica.

## 3. Casi d'Uso Rilevanti ed Esempi sul Campo
---

### **Caso d'Uso 1: Medico di Pronto Soccorso in Zona Sinistrata**
* **Scenario**: Un terremoto ha distrutto le reti cellulari. Il dottor Marco (medico traumatologo) possiede uno smartphone con il 90% di batteria ed un kit chirurgico portatile.
* **Uso delle API**:
  L'app di Marco invoca la funzione del client:
  ```java
  resourceDiscoveryClient.publishResourceAnnouncement(
      "#medici-pronto-soccorso",
      "Medico Traumatologo con Kit Chirurgico",
      List.of("Kit Primo Soccorso", "Laringoscopio", "Defibrillatore"),
      90, // Batteria 90%
      "Campo Volontari - Settore Nord",
      12 * 3600 * 1000L // TTL: 12 Ore
  );
  ```
* **Rilevanza**: L'annuncio viene impacchettato nel DTO BDF `ResourceAnnouncementMessage` firmato con la chiave Ed25519 di Marco e si diffonde via P2P. Chiunque nel raggio radio cerca un medico trova la scheda di Marco con lo stato aggiornato della batteria e dell'attrezzatura.

---

### **Caso d'Uso 2: Punto di Ricarica Energia / Gruppo Elettrogeno**
* **Scenario**: Blackout totale prolungato. Un volontario (Giuseppe) dispone di un gruppo elettrogeno a benzina da 3 kW e mette a disposizione prese USB per ricaricare gli smartphone dei soccorritori.
* **Uso delle API**:
  ```java
  resourceDiscoveryClient.publishResourceAnnouncement(
      "#punti-ricarica-energia",
      "Stazione Ricarica Smartphone e Radio",
      List.of("Gruppo Elettrogeno 3kW", "Multipresa USB 10 porte"),
      100,
      "Tenda Protezione Civile - Piazza Centrale",
      6 * 3600 * 1000L // TTL: 6 Ore
  );
  ```
* **Rilevanza**: Evita che gli smartphone di emergenza si spengano, permettendo ai coordinatori di scoprire dove ricaricare le batterie dei dispositivi.

---

### **Caso d'Uso 3: Ricerca e Consulta delle Risorse da parte di un'ONG**
* **Scenario**: Un operatore della Croce Rossa deve trovare tutti i medici disponibili nel raggio di copertura ad-hoc.
* **Uso delle API**:
  L'app dell'operatore interroga il registro locale:
  ```java
  List<ResourceAnnouncementMessage> medici = resourceRegistry.getActiveResourcesForTopic("#medici-pronto-soccorso");
  ```
* **Rilevanza**: `ResourceRegistry` filtra automaticamente gli annunci scaduti ($t > \text{timestamp} + \text{ttl}$), mostrando all'operatore la lista pulita dei medici attivi con le relative attrezzature e percentuali di batteria.

### A. `ResourceAnnouncementMessage.java`
* **Path**: `briar-api/src/main/java/org/briarproject/briar/api/resource/ResourceAnnouncementMessage.java`
* **Natura**: **`[FILE NUOVO]`** (Modulo `briar-api`)
* **Ruolo**: Contratto DTO BDF immutabile per l'annuncio delle risorse.

```java
// FILE NUOVO - Path: briar-api/src/main/java/org/briarproject/briar/api/resource/ResourceAnnouncementMessage.java

package org.briarproject.briar.api.resource;

import org.briarproject.bramble.api.identity.Author;
import org.briarproject.bramble.api.sync.MessageId;
import org.briarproject.nullsafety.NotNullByDefault;

import javax.annotation.concurrent.Immutable;
import java.util.Collections;
import java.util.List;

/**
 * DTO BDF Immutabile per l'annuncio Pub/Sub delle risorse e competenze di un nodo.
 * <p>
 * Questo file rappresenta un'ESTENSIONE ORIGINALE sviluppata per il progetto di tesi.
 * Incapsula le competenze, l'hardware disponibile, il livello di batteria dello smartphone,
 * la posizione approssimata ed il timestamp di scadenza (TTL).
 *
 * @author Progetto Tesi Giornalismo P2P
 */
@Immutable
@NotNullByDefault
public class ResourceAnnouncementMessage {

    private final MessageId messageId;           // SHA-256 univoco del messaggio BDF
    private final Author providerAuthor;          // Autore/Nodo proprietario della risorsa
    private final String topicCategory;          // Categoria Topic (es. "#medici-pronto-soccorso")
    private final String skillTitle;             // Titolo/Competenza (es. "Medico Traumatologo")
    private final List<String> hardwareAvailable;// Lista hardware (es. ["Defibrillatore", "Kit"])
    private final int batteryLevelPercent;       // Livello batteria smartphone (0-100%)
    private final String locationDescriptor;     // Ubicazione approssimata o settore
    private final long timestampMs;              // Timestamp Unix di emissione (ms)
    private final long ttlDurationMs;            // Durata di validità / TTL (ms)
    private final byte[] signature;              // Firma digitale Ed25519 dell'autore

    /**
     * Costruttore completo per l'annuncio della risorsa.
     */
    public ResourceAnnouncementMessage(MessageId messageId,
                                       Author providerAuthor,
                                       String topicCategory,
                                       String skillTitle,
                                       List<String> hardwareAvailable,
                                       int batteryLevelPercent,
                                       String locationDescriptor,
                                       long timestampMs,
                                       long ttlDurationMs,
                                       byte[] signature) {
        this.messageId = messageId;
        this.providerAuthor = providerAuthor;
        this.topicCategory = topicCategory;
        this.skillTitle = skillTitle;
        this.hardwareAvailable = Collections.unmodifiableList(hardwareAvailable);
        this.batteryLevelPercent = batteryLevelPercent;
        this.locationDescriptor = locationDescriptor;
        this.timestampMs = timestampMs;
        this.ttlDurationMs = ttlDurationMs;
        this.signature = signature;
    }

    /** Ritorna l'ID SHA-256 univoco del messaggio BDF. */
    public MessageId getMessageId() { return messageId; }

    /** Ritorna l'identità dell'autore (Author Ed25519) che ha pubblicato la risorsa. */
    public Author getProviderAuthor() { return providerAuthor; }

    /** Ritorna il Topic Pub/Sub della risorsa (es. "#punti-ricarica-energia"). */
    public String getTopicCategory() { return topicCategory; }

    /** Ritorna il titolo descrittivo della competenza o risorsa. */
    public String getSkillTitle() { return skillTitle; }

    /** Ritorna la lista delle attrezzature ed hardware disponibili. */
    public List<String> getHardwareAvailable() { return hardwareAvailable; }

    /** Ritorna la percentuale di autonomia residua dello smartphone del provider. */
    public int getBatteryLevelPercent() { return batteryLevelPercent; }

    /** Ritorna la descrizione testuale dell'ubicazione o settore operativo. */
    public String getLocationDescriptor() { return locationDescriptor; }

    /** Ritorna il timestamp di generazione del messaggio. */
    public long getTimestampMs() { return timestampMs; }

    /** Ritorna la durata di validità (TTL in ms) prima che la risorsa scada. */
    public long getTtlDurationMs() { return ttlDurationMs; }

    /** Ritorna la firma crittografica asimmetrica Ed25519. */
    public byte[] getSignature() { return signature; }

    /** Verifica se l'annuncio della risorsa è tuttora valido o se è scaduto. */
    public boolean isExpired(long currentTimeMs) {
        return currentTimeMs > (timestampMs + ttlDurationMs);
    }
}
```

### B. `ResourceDiscoveryClient.java`
* **Path**: `briar-api/src/main/java/org/briarproject/briar/api/resource/ResourceDiscoveryClient.java`
* **Natura**: **`[FILE NUOVO]`** (Modulo `briar-api`)
* **Ruolo**: Interfaccia API pubblica per la pubblicazione delle proprie risorse sul network P2P.

```java
// FILE NUOVO - Path: briar-api/src/main/java/org/briarproject/briar/api/resource/ResourceDiscoveryClient.java

package org.briarproject.briar.api.resource;

import org.briarproject.bramble.api.db.DbException;
import org.briarproject.nullsafety.NotNullByDefault;
import java.util.List;

/**
 * Interfaccia API per la pubblicazione e sottoscrizione Pub/Sub delle risorse di rete.
 * <p>
 * Questo file rappresenta un'ESTENSIONE ORIGINALE sviluppata per il progetto di tesi.
 *
 * @author Progetto Tesi Giornalismo P2P
 */
@NotNullByDefault
public interface ResourceDiscoveryClient {

    /**
     * Pubblica le proprie competenze/risorse su uno specifico Topic della comunità.
     *
     * @param topicCategory      Categoria del Topic (es. "#medici-pronto-soccorso")
     * @param skillTitle         Titolo della competenza (es. "Medico Traumatologo")
     * @param hardwareAvailable  Lista attrezzature disponibili
     * @param batteryPercent     Percentuale autonomia batteria
     * @param locationDescriptor Ubicazione o settore
     * @param ttlMs              Durata di validità dell'annuncio in ms
     * @throws DbException       In caso di errore durante la scrittura nel DB cifrato
     */
    void publishResourceAnnouncement(String topicCategory,
                                     String skillTitle,
                                     List<String> hardwareAvailable,
                                     int batteryPercent,
                                     String locationDescriptor,
                                     long ttlMs) throws Exception;

    /**
     * Sottoscrive l'utente locale ad un Topic di risorse, abilitandone la sincronizzazione BSS.
     *
     * @param topicCategory Categoria del Topic
     */
    void subscribeToResourceTopic(String topicCategory) throws DbException;
}
```

### C. `ResourceRegistry.java`
* **Path**: `briar-api/src/main/java/org/briarproject/briar/api/resource/ResourceRegistry.java`
* **Natura**: **`[FILE NUOVO]`** (Modulo `briar-api`)
* **Ruolo**: Interfaccia API per la consultazione e gestione del registro locale delle risorse.

```java
// FILE NUOVO - Path: briar-api/src/main/java/org/briarproject/briar/api/resource/ResourceRegistry.java

package org.briarproject.briar.api.resource;

import org.briarproject.nullsafety.NotNullByDefault;
import java.util.List;

/**
 * Interfaccia API per la consultazione del registro locale delle risorse apprese dalla rete P2P.
 * <p>
 * Questo file rappresenta un'ESTENSIONE ORIGINALE sviluppata per il progetto di tesi.
 *
 * @author Progetto Tesi Giornalismo P2P
 */
@NotNullByDefault
public interface ResourceRegistry {

    /**
     * Registra un annuncio di risorsa ricevuto via P2P BSS se valido e non scaduto.
     */
    void registerIncomingResourceAnnouncement(ResourceAnnouncementMessage announcement);

    /**
     * Ritorna la lista delle risorse attive e non scadute per un determinato Topic.
     */
    List<ResourceAnnouncementMessage> getActiveResourcesForTopic(String topicCategory);

    /**
     * Invalida o rimuove un annuncio di risorsa dal registro locale.
     */
    void invalidateResource(String providerAuthorId, String topicCategory);
}
```
